# 模块说明 · 关键事件 Hook（server/hooks/）

> 本文件按硬规则⑤要求，**先于 Hook 代码产生**，用于固定 Hook 的职责、语义、契约与配置项。

## 一、模块职责

在**业务层**（限流之后，D13）对「报名提交」这一关键事件做突发保护：

- 当**在途并发提交数**超过阈值时，判定为突发流量，进入**冷却期**；
- 冷却期内所有新的提交直接拦截，返回**新错误码 `1003`**，**不再写库**；
- 触发与恢复各输出一行 **JSON 结构化日志**（stdout，D14/D20），供压测报告与后续告警引用。

## 二、目录结构

```
server/hooks/
├── index.js               # Hook 注册与编排（按注册顺序执行，可插拔）
└── signupBurstGuard.js    # 关键事件：报名突发保护
```

## 三、语义（D18）

| 项 | 定义 |
|---|---|
| 计数对象 | **在途并发提交数**（进入提交处理即 +1，处理结束即 −1），不是累计报名人数（N10） |
| 触发条件 | 在途并发提交数 **> 阈值**（默认 100） |
| 触发动作 | 进入冷却（默认 60s）；触发该次的请求本身也被拒绝 |
| 冷却期行为 | 新的提交一律拦截，返回 `code=1003` / HTTP 503，**零写库** |
| 恢复条件 | 冷却到期后自动恢复受理，并输出一行恢复日志 |
| 默认状态 | **开启** |

## 四、契约（新增，不改既有）

| 项 | 值 |
|---|---|
| 错误码 | `1003` |
| 文案 | 当前报名人数较多，请稍后再试 |
| HTTP 状态 | `503` |
| 响应体 | `{ code: 1003, message: '当前报名人数较多，请稍后再试', data: null }` |

既有 `1001` / `1002` / `5000` 的语义与状态码**保持不变**（Q4）。

## 五、配置项（环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `HOOK_SIGNUP_BURST_ENABLED` | `1` | `0` 关闭该 Hook（压测时用于采集「Hook 关闭」对照组，K7/K8） |
| `HOOK_SIGNUP_BURST_THRESHOLD` | `100` | 在途并发提交阈值 |
| `HOOK_SIGNUP_BURST_COOLDOWN_MS` | `60000` | 冷却时长（毫秒） |

## 六、结构化日志格式（D14）

单行 JSON，字段固定：

```json
{"event":"signup_burst_guard","action":"trip","at":"<ISO>","inFlight":101,"threshold":100,"cooldownMs":60000,"cooldownUntil":"<ISO>","rejected":0}
{"event":"signup_burst_guard","action":"recover","at":"<ISO>","inFlight":12,"threshold":100,"rejected":184}
```

- `action=trip`：触发突发保护并进入冷却。
- `action=recover`：冷却到期恢复受理，并带上冷却期内被拦截的请求数 `rejected`。
- 日志**只写 stdout**（D20），不落文件，不引入日志轮转。

## 七、可测试性

- 内部时钟可注入（`now()` 可替换），使冷却/恢复可在单元测试中用假时钟断言，**不依赖 sleep**。
- 暴露 `tryAcquire()` / `release()` / `snapshot()` / `reset()` 供测试与观测使用。
