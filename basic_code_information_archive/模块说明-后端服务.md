# 模块说明 · 后端服务（server/）

## 一、模块职责

后端服务是升级版（v0.2）引入的**唯一数据持久化与业务校验**出口。它在副机上以 Node.js 进程运行，负责：

- 托管前端静态资源（`user.html` / `admin.html` / `assets/`）；
- 提供报名相关 REST API（提交、查询、列表、导出、场次字典）；
- 以 **SQLite 单文件**持久化报名数据（WAL 模式，重启不丢）；
- 承担**服务端二次校验**（前端校验可被绕过，唯一性与必填以服务端为准）。

约定：**前端不直接接触数据库，一切读写经 HTTP API**；前端 `assets/js/store.js` 已由「localStorage 数据层」重构为「API 客户端」。

## 二、目录结构

```
server/
├── package.json              # 依赖与启动脚本
├── config.js                 # 集中常量：场次/身份字典、错误码、备份份数、字段限制
├── db.js                     # SQLite 连接（WAL）、建表、启动备份
├── regno.js                  # 报名编号生成（REG + YYYYMMDD + 4 位当日流水）
├── server.js                 # 应用入口：中间件、静态托管、路由挂载、错误处理
└── routes/
    ├── registrations.js      # 报名相关路由
    └── sessions.js           # 场次字典路由
```

## 三、运行方式

```bash
cd server
npm install
npm start
```

环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 监听端口 |
| `DB_PATH` | `../data/app.db` | SQLite 文件路径（相对 server/ 解析） |
| `BACKUP_DIR` | `../data/backups` | 备份目录 |
| `CORS_ORIGIN` | `*` | 允许的来源（生产建议收紧） |

## 四、数据模型（表 `registrations`）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | INTEGER | 是 | 主键自增 |
| `reg_no` | TEXT | 是 | 报名编号，唯一，`REG + YYYYMMDD + 4 位当日流水` |
| `name` | TEXT | 是 | 非空 |
| `role` | TEXT | 否 | `teacher` / `student` / `other`，可空 |
| `department` | TEXT | 否 | 可空 |
| `phone` | TEXT | 是 | 11 位数字；**UNIQUE 唯一索引** |
| `session` | TEXT | 是 | `morning` / `afternoon` |
| `created_at` | TEXT | 是 | ISO 时间，系统生成 |

- **空库启动**：不注入任何种子数据。
- **WAL 模式**：`PRAGMA journal_mode = WAL`，提升并发读写表现。
- **启动备份**：每次启动将当前 DB 文件复制到 `BACKUP_DIR`，命名为 `app-YYYYMMDD-HHmmss.db`，**仅保留最近 7 份**，超出的最旧文件删除。

## 五、API 契约

统一响应体 `{ code, message, data }`，`code = 0` 表示成功。

| 方法 | 路径 | 说明 | 入参 | 出参 |
|---|---|---|---|---|
| POST | `/api/registrations` | 提交报名 | name, role, department, phone, session | 成功返回记录（含 `reg_no`） |
| GET | `/api/registrations/lookup` | 按手机号查询 | phone | 命中返回记录，未命中 `data=null` |
| GET | `/api/registrations` | 名单列表（筛选） | role?, session?, keyword? | 记录数组 |
| GET | `/api/registrations/export` | 导出 CSV | role?, session?, keyword? | CSV 文件流 |
| GET | `/api/sessions` | 场次字典 | —— | 场次数组 |

错误码：

| code | 含义 | HTTP 状态 |
|---|---|---|
| 0 | 成功 | 200 |
| 1001 | 参数校验失败 | 400 |
| 1002 | 手机号重复 | 409 |
| 5000 | 服务器内部错误 | 500 |

## 六、业务规则（服务端实现要点）

- **R1 手机号全局唯一**：`phone` 建 UNIQUE 索引；插入命中唯一约束时返回 `code=1002`（并发兜底）。
- **R2 必填校验**：仅卡姓名 / 手机号 / 场次；身份、院系可空。手机号必须 `^\d{11}$`；`role` 若填写须在字典内；`session` 必须在字典内。
- **R6 导出**：严格按当前筛选（role/session/keyword 三条件 AND）；CSV 前置 **UTF-8 BOM**（`\uFEFF`），响应头 `Content-Disposition: attachment; filename=...`。
- **关键字**：命中范围 = 姓名 + 手机号 + 院系（`LIKE` 包含，参数化）。

## 七、安全与非功能

- **参数化 SQL**：全部使用 prepared statement，无字符串拼接，防注入。
- **体积限制**：`express.json({ limit: '16kb' })`。
- **限流**：`express-rate-limit`，对全部 `/api/` 生效（管理端无鉴权，限流尤为必要）。
- **CORS**：来源由 `CORS_ORIGIN` 控制。
- **日志**：请求日志（方法 / 路径 / 状态 / 耗时）与错误日志输出到控制台，可由部署脚本重定向落文件。
- **统一错误处理**：所有异常经末尾错误中间件返回 `{code:5000,...}`，不泄漏堆栈。

## 八、约束

- 仅依赖 express / better-sqlite3 / cors / express-rate-limit，不引入 ORM；
- 不在数据库中保存明文之外的敏感信息（本 Demo 仅姓名与手机号）；
- 管理端无鉴权为**用户明确选择**，演示结束后应关闭穿透隧道。
