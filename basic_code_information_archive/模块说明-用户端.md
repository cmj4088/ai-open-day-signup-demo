# 模块说明 · 用户端（user.html）

## 一、模块职责

用户端是面向报名者（教师 / 学生 / 其他）的单页入口，用一个 `user.html` 承载三个视图（**报名页 / 成功页 / 查询页**），通过**页面内区块切换**（切换 `.active` 类显隐视图，非 hash 路由）完成：

1. 填写并提交报名表单；
2. 展示报名成功回执；
3. 按手机号查询自己的报名记录。

数据读写一律通过 API 客户端 `store.js` 调用后端接口，用户端**不直接 `fetch`、不持有任何本地持久化数据**。

## 二、载体文件

- `user.html`：页面结构（三个视图区块）。
- `assets/js/user.js`：表单校验、提交、视图切换、查询渲染。
- `assets/css/style.css`：样式（校园深蓝主题）。

## 三、页面构成

### 3.1 报名页（默认视图，`#view-signup`）

- 标题与简介：校园「AI 应用教学开放日」报名；
- 顶部**场次介绍区**（`#session-info`）：由 `user.js` 从 `Store.SESSIONS` 渲染，先展示一行「活动主题」，再逐场次展示「场次标签 + 时间 · 地点」；
- 表单（`#signup-form`，`novalidate` 关闭浏览器原生校验，统一由 `user.js` 输出红色中文提示），字段共 5 项：
  1. **姓名**（文本，必填，`#input-name`，错误提示 `#error-name`）
  2. **身份**（下拉，`#input-role`，可留空）：空选项「请选择身份」+ `Store.ROLES`（教师 / 学生 / 其他）
  3. **院系**（文本，`#input-department`，可留空，占位「选填，比如计算机系」）
  4. **手机号**（文本，必填，`#input-phone`，`maxlength=11`，占位「请输入 11 位手机号」）
  5. **参加场次**（下拉，必填，`#input-session`）：空选项「请选择场次」+ `Store.SESSIONS`（展示文案为「场次标签 + 时间」）
- 操作按钮：**提交报名**（提交表单）；**查询报名状态**（`#go-query`，跳转查询页）。

### 3.2 成功页（`#view-success`）

- 展示报名成功提示（🎉 + 活泼亲切文案）；
- 展示核心回执信息（`#success-name` / `#success-session`）：**报名人姓名 + 参加场次**（场次展示为「标签 · 时间 · 地点」整串）；
- 提供操作入口：**返回首页**（`#success-home`，重置表单并回报名页）/ **查询报名状态**（`#success-query`，前往查询页）。

### 3.3 查询页（`#view-query`）

- 输入项：**手机号**（`#query-phone`，`maxlength=11`）；
- 操作按钮：**查询**（`#btn-query`），支持在输入框内回车直接查询；
- 结果容器：`#query-result`；
- 命中时展示：**姓名 / 身份 / 院系 / 参加场次 / 报名时间**（参加场次展示为场次标签）；
- 未命中时展示固定提示文案：**「暂未查到报名记录哦」**；
- 其他提示：未输入手机号时展示「请先输入手机号再查询哦」；
- 返回入口：**返回报名页**（`#query-back`）.

### 3.4 视图切换方式

由 `user.js` 的 `showView(target)` 完成：先对三个视图区块统一移除 `.active`，再为目标视图加上 `.active`，并 `window.scrollTo(0, 0)` 回到页顶。**不涉及 hash 路由或页面跳转**。

## 四、字段与校验规则

| 字段 | 必填 | 类型 | 校验规则 | 错误提示（红色、字段下方） |
|---|---|---|---|---|
| 姓名 | 是 | 文本 | 去首尾空格后非空（`trim() !== ''`） | 「请填写姓名哦」 |
| 身份 | 否 | 枚举（教师/学生/其他） | 不校验 | —— |
| 院系 | 否 | 文本 | 不校验 | —— |
| 手机号 | 是 | 文本 | 匹配 `/^\d{11}$/`（纯 11 位数字）；失焦时调后端查重（`getByPhone` 命中即视为已报名） | 格式错：「请填写正确的 11 位手机号哦」；重复：「该手机号已报名，请勿重复提交」 |
| 参加场次 | 是 | 枚举（上午场/下午场） | 值非空 | 「请选择参加场次哦」 |

**校验触发时机：**

- **失焦（blur）时实时触发**：姓名、手机号、参加场次三项失去焦点时立即校验并显示/清除错误提示；
- 手机号失焦额外做一次**异步查重**（调 `getByPhone`），命中则提示「该手机号已报名，请勿重复提交」；若请求返回前输入已被改动，则丢弃该次结果；
- 提交时对三项必填做一次整体校验，任一不通过则**阻止提交**并聚焦首个错误字段（顺序：姓名 → 手机号 → 参加场次）；
- 提交期间按钮禁用并显示「提交中…」，防重复点击造成并发提交；
- 错误提示以**红色中文**渲染在该字段**正下方**（`.form-error` + `.show`）。

## 五、交互流程

### 5.1 报名流程

1. 用户进入报名页，填写 5 个字段；
2. 字段失焦时实时校验（必填项空 / 手机号格式）；
3. 点击「提交报名」→ 提交前整体校验，未通过则聚焦首个错误字段并中断；
4. 校验通过后调用 `Store.add(record)` → 后端 `POST /api/registrations`：
   - 后端以手机号查重（DB 唯一索引兜底）。**重复**（`code=1002`）时页面提示 **「该手机号已报名，请勿重复提交」**，停留报名页；
   - **参数校验失败**（`code=1001`）或**网络异常**时，在手机号字段下方提示对应文案；
   - **成功**则返回含 `regNo` 的完整记录；
5. 成功后填充回执（姓名 + 场次整串）并切换到**成功页**。

### 5.2 查询流程

1. 用户进入查询页，输入手机号，点击「查询」（或回车）；
2. 空输入 → 提示「请先输入手机号再查询哦」；
3. 先做格式校验：非 11 位数字时提示「请填写正确的 11 位手机号哦」；
4. 调用 `Store.getByPhone(phone)` → 后端 `GET /api/registrations/lookup`：
   - 命中：渲染 姓名 / 身份 / 院系 / 参加场次 / 报名时间；
   - 未命中：展示「暂未查到报名记录哦」；
   - 网络异常：展示「网络异常，请稍后重试」。

## 六、依赖与约束

- 依赖 API 客户端 `store.js` 暴露的 `ready` / `getByPhone(phone)` / `add(record)` / `sessionLabel(key)` / `roleLabel(key)` / `SESSIONS` / `ROLES`；
- 场次取值与展示文案须与服务端场次字典保持一致（经 `/api/sessions` 获取），禁止页面内硬编码第二套场次文案；
- 不新增额外必填项：严格只卡 姓名 / 手机号 / 参加场次 三项；
- 无容量概念，页面不得出现「剩余名额 / 已满」之类文案。
