# 模块说明 · 自动化测试（server/test/）

> 本文件按硬规则⑤要求，**先于测试代码产生**，用于固定测试范围、目录约定与运行方式。

## 一、模块职责

用 **Node 内置 `node:test`**（零新依赖，符合 Q5「只允许 devDependency」）为后端建立回归安全网，证明本次重构**未改变对外行为**：

- 覆盖 `server/lib/` 全部纯函数（校验、筛选构造、CSV 转义、时间格式化）；
- 覆盖 `server/repositories/` 的 SQL 行为（查重、列表、分页、流式遍历、唯一约束兜底）；
- 覆盖 `server/hooks/` 的突发保护逻辑（触发、冷却、拒绝、恢复）；
- 以 **HTTP 集成测试**逐条断言原 5 个接口的**契约未变**（AC1）。

## 二、目录结构（规划）

```
server/test/
├── helpers/
│   └── tempdb.js          # 临时库与临时 DATA_DIR 工具（每个用例独立、用后清理）
├── lib.test.js            # 纯函数单测（validate / csv / datetime）
├── regno.test.js          # 编号生成与边界（单日 >9999 退化为 5 位流水）
├── repo.test.js           # 仓储层 SQL 行为（内存库）
├── hooks.test.js          # signupBurstGuard 单元测试（含时钟注入）
├── contract.test.js       # 原 5 接口契约断言（AC1）
└── api.test.js            # HTTP 集成（分页可选参数、/healthz、1003 拦截）
```

## 三、运行方式

| 场景 | 命令 | 说明 |
|---|---|---|
| 仓库根统一入口 | `npm test` | 等价于 `node --test server/test/` |
| 指定文件 | `node --test server/test/lib.test.js` | 调试单个文件 |

- 每个测试文件由 `node --test` 在**独立子进程**中运行，互不污染全局状态。
- 测试**不触碰** `data/app.db`：一律把 `DATA_DIR` / `DB_PATH` / `BACKUP_DIR` 指向系统临时目录。
- 测试**不监听固定端口**：HTTP 集成用 `app.listen(0)` 由内核分配随机端口，避免与 3000/3100 冲突。

## 四、依赖与约束

- **零新增依赖**：只用 `node:test` + `node:assert/strict` + 全局 `fetch`（Node ≥ 18）。
- 不引入 supertest / jest / mocha。
- 测试中禁用 Hook 的默认阈值扰动：需要时通过环境变量显式设定（如把阈值调到 3 以便快速触发）。

## 五、与验收标准的对应

| 验收项 | 由哪些测试覆盖 |
|---|---|
| AC1 契约未变 | `contract.test.js` |
| AC2 lib 纯函数全覆盖 | `lib.test.js` |
| AC11 Hook 生效 | `hooks.test.js`（单元）+ `api.test.js`（集成） |
| AC13 测试含 Hook | `hooks.test.js` / `api.test.js` |
