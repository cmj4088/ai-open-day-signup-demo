# 模块说明 · 压测脚本（scripts/stress/）

> 本文件按硬规则⑤要求，**先于压测代码产生**，用于固定压测拓扑、场景编号与产物脱敏规则。

## 一、模块职责

以 **autocannon**（devDependency，D1）驱动，对部署在副机的被测服务（SUT）执行 PRD 第四章定义的 S1–S10 场景，产出台账化结果（JSON）与控制台摘要，作为 `docs/压力测试报告.md` 的唯一数据来源。

## 二、拓扑（D8/D11）

```
[本机 Windows]  ──HTTP──▶  [副机 Linux · 端口 3100]
  autocannon 客户端            Node 被测服务（DATA_DIR=<项目>/data/.stress）
```

- 客户端与服务端分离，避免争抢副机仅有的 4 个逻辑核。
- 服务端以 `DATA_DIR` 与端口 3100 与既有 3000 实例隔离（D2/D11）。
- 压测前**显式关闭限流**（`RATE_DISABLED=1`），否则 429 会截断结论（PRD 4.2）。

## 三、目录结构（规划）

```
scripts/stress/
├── lib.js               # 公共库：目标地址/手机号池/fetch 助手/并发池/结果摘要与落盘
├── scenarios.js         # S1–S10 场景定义（请求构造 + autocannon 入参）
├── seed.js              # 造数据：向 SUT 灌入 1k / 10k / 50k 记录（供 S3/S4）
├── runner.js            # 编排：按计划串行执行场景，采集指标，落 JSON
├── sample-remote.sh     # 在被测主机上采样 RSS / DB / WAL / load（资源曲线）
└── results/             # 压测产物（脱敏后提交，Q6）
```

运行方式：

```bash
# 被测服务已在副机 3100 就绪（RATE_DISABLED=1，Hook 按需开关）
SUT_URL=http://<SUT>:3100 node scripts/stress/runner.js --label baseline
SUT_URL=http://<SUT>:3100 node scripts/stress/runner.js --label retest
SUT_URL=http://<SUT>:3100 node scripts/stress/runner.js --label hook --only=s10
```

## 四、场景与产出

| 编号 | 场景 | 说明 |
|---|---|---|
| S1 | 写入基线 | 并发 10/50/100，各 30s |
| S2 | 唯一性并发正确性 | 同手机号并发 50，期望恰好 1 次 `code=0` |
| S3 | 列表读取 | 1k/10k/50k 三档，并发 50 |
| S4 | 导出 CSV | 三档数据量，并发 10 |
| S5 | 单条查询 | 并发 50，命中/未命中各半 |
| S6 | 混合场景 | 提交:列表:查询 = 5:4:1，并发 50，60s |
| S7 | 极限爬升 | 10→50→100→200→400→800，每级 20s |
| S8 | 限流影响确认 | 对未关闭限流的实例打 S1 |
| S9 | 长稳 | 并发 50 持续 5 分钟 |
| S10 | Hook 触发与冷却 | 高于阈值并发持续提交，验证 1003 与恢复 |

## 五、脱敏规则（Q6 / AC9）

报告中**禁止出现**：内网 IP、主机名、登录账号名。脚本落盘前统一替换为占位符：

| 原始 | 占位符 |
|---|---|
| 被测服务地址 | `http://<SUT>:3100` |
| 客户端主机 | `<CLIENT>` |
| 副机主机名 / 账号 | `<SUT_HOST>` / `<SUT_USER>` |

## 六、硬件参照系（K1）

副机为低压 4 逻辑核，绝对吞吐反映的是**该硬件能力**而非软件上限。脚本附带一个「裸 HTTP 回显基准」场景（`/healthz`），作为对照写入报告。
